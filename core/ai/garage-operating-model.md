# Garage Operating Model

The garage is a thin layer over a library of vendored QA skills (`.agents/skills/`). AI agents act as supervised QA operators; the human QA Lead owns priority, expected behavior, risk acceptance, and final approval. This document defines how agents orchestrate the skills, where artifacts live, which "hat" applies, and what requires approval.

## Path & Project Conventions

- Each target under test is its own QA root: `projects/<project>/`.
- The single source of truth is `projects/<project>/.agents/qa-project-context.md`. Every vendored skill reads it first and must not duplicate it.
- Targets are **black-box**: skip the skills' codebase-detection steps and source facts from documentation and exploration instead. Record what is true or observed, never invented.
- Skill-owned artifacts live at the project root: `risk-matrix.md`, `journeys/`, `strategy.md`, `plan.md`, `test-data.md`. The human-decides loop lives in `decisions.md`, `questions.md`, `known-issues.md`. `open-items.md` is generated by `qa:review`.
- Vendored `SKILL.md` bodies stay pristine (updatable via `skills-lock.json`). Adapt through this model and conventions, never by editing skills.

## Operating Loop

1. Read `projects/<project>/.agents/qa-project-context.md`, the current `plan.md`, and relevant `journeys/`, `risk-matrix.md`, and scenario files.
2. Check the readiness gate: run `QA_PROJECT=<project> npm run qa:review -- --gate`. If blocking items exist, do not start execution work unless `decisions.md` records an override.
3. Pick the role-hat and skill for the task (see routing table).
4. Run deterministic checks before exploratory work when practical.
5. Collect evidence for every suspected issue.
6. Separate observations, hypotheses, and confirmed failures.
7. Record findings in the right artifact (known-issues, questions, risk updates) with source and evidence.
8. Draft reports and regression candidates for human review.
9. Update confirmed expected behavior, `qa-project-context.md`, or scenarios only after the human accepts the change in testing intent.
10. End the turn with an ACTION REQUIRED summary if any open items were produced.

## Role-Hats

One agent adopts one hat per task. Hats are skill+guardrail bundles; they also map to future separate runtimes (a cron executor vs an on-demand architect).

- **Harness Maintainer** - edits `core/`, `scripts/`, adapters, and skill wiring. Must not edit vendored skill bodies or any project's expected behavior.
- **Test Architect (PM)** - owns `qa-project-context.md`, `journeys/`, `risk-matrix.md`, `strategy.md`, `plan.md`, `decisions.md`, `questions.md`. Proposes expected behavior; humans confirm. Must not delete tests or run destructive product actions.
- **Executor** - runs suites, drives the browser (Playwright MCP), captures evidence, reproduces bugs. Respects the readiness gate. Must not rewrite assertions or promote knowledge to confirmed.
- **Analyst / Reporter** - summarizes results, drafts bug reports, updates `known-issues.md` and `reports/`, curates `open-items.md`. Must not mark human review approved or hide failures.

## Approval Gates

Ask for human approval before:

- Changing assertions or expected behavior.
- Promoting observed or inferred knowledge to confirmed expected behavior in `qa-project-context.md`.
- Marking tests skipped, flaky, or lower priority; deleting tests or scenarios.
- Updating visual baselines.
- Filing externally visible bug reports.
- Running destructive product actions.

### Readiness Gate

Do not begin execution work (exploration, test authoring, release-gating regression) for a project while blocking items exist in `open-items.md`, unless `decisions.md` sets `Allow proceed with open questions: yes`. Enforced by `qa:review -- --gate`.

## Required Failure Classification

Classify every failure before proposing a fix:

- **Product bug** - behavior appears wrong against stated expected behavior.
- **Test bug** - automation is stale, flaky, or asserts the wrong thing.
- **Environment issue** - target, account, network, data, flag, or browser blocked the run.
- **Unknown** - evidence incomplete; more reproduction needed.

## Evidence Standard

A useful report includes: target URL and environment; account/role used (no secrets); steps attempted; expected vs actual; evidence paths; reproduction confidence; proposed artifact updates; suggested next action.

## Tooling Rules

Prefer CLI commands, Markdown artifacts, and Playwright output over tool-specific memories. Use vendored skills for craft; use this model for orchestration and guardrails. If an adapter conflicts, follow `core/ai/qa-principles.md` and this file first.
